
## 数组 vs slice 作为函数参数

数组是值类型，传参时会整体拷贝一份。函数内部对数组元素的修改，不会影响外部的原数组。

```go
func modifyArray(arr [3]int) {
	arr[0] = 100 // 只改了拷贝
}

a := [3]int{1, 2, 3}
modifyArray(a)
// a 仍是 [1 2 3]，未改变
```

slice 本质是一个结构体 `{指针, len, cap}`，传参时拷贝的是这个结构体本身，但指针指向的底层数组是共享的。所以函数内部对已有元素的修改会反映到外部。

```go
func modifySlice(s []int) {
	s[0] = 100 // 通过共享的底层数组修改，会影响外部
}

s := []int{1, 2, 3}
modifySlice(s)
// s 变为 [100 2 3]
```

例外：如果函数内部对 slice 做 `append` 触发了扩容（超过原 cap），底层数组会被重新分配，函数内部的 slice 会指向新数组，外部的 slice 仍指向旧数组，这种改变不会反映到外部（除非通过返回值传回去）。

```go
func appendSlice(s []int) {
	s = append(s, 4) // 若触发扩容，s 指向新数组
}

s := make([]int, 3, 3) // cap=3，一定会扩容
s[0], s[1], s[2] = 1, 2, 3
appendSlice(s)
// s 仍是 [1 2 3]，长度和内容都没变
```

结论：对 slice 已有元素的修改会反映到外部；但对 slice 长度/容量的改变（如 append 导致扩容），如果不通过返回值传回去，外部感知不到。
